# Henneth Desk 2.CI.0

Private company-intelligence surface for the Henneth desk.

The app is static and has no package install. Its only runtime data dependency is:

```text
data/company_intelligence.json
```

The reading workspace deliberately avoids decorative background images. Company logos remain as
identity cues, while the shell, charts, and sign-in gate use lightweight CSS colour and motion only.
`scripts/check_ci_no_background_images.mjs` protects this performance contract.

That file is generated by `python scripts/build_ci_slice.py` from the root `state/` layer. The app shell and sign-in form are public so a visitor can authenticate, but `middleware.js` gates `/data/*` by verifying the existing Supabase ES256 JWT and requiring:

```text
payload.sub === process.env.CI_OWNER_USER_ID
```

Do not put a real owner UUID in this repo. Set `CI_OWNER_USER_ID` in the hosting environment. There is no service-role key, no signup flow, automated database migration, or execution/order path.

Auth failures fail closed: missing, invalid, expired, or unconfigured tokens return `401`; a valid signed token for any non-owner account returns `403`.

The CI-local `POST /api/ask` endpoint applies the same owner check before reading company data or calling Groq. It accepts only the pilot symbol/question contract, caps raw UTF-8 request bodies at 16 KiB, projects one requested row through `api/ask_contract.js`, and permits only qualitative JSON output. Numeric/advice/cross-company output is rejected and the server always builds the answer and citation sections.

The Ask Henneth tab sends an owner bearer to the relative endpoint and keeps pending/error/answer state per company. A stale response cannot replace another company's answer; a 401 refreshes the session once. The UI renders the nine server-owned sections in contract order, shows explicit empty/blocked/unknown states, and turns citation links into anchors only after `safeHref` validation. `scripts/check_ask_henneth_ui.mjs` checks the real 20-row slice, request/auth behavior, escaping, section order, and responsive rules offline.

The Scenarios tab is a deterministic snapshot sensitivity, available only after the same
financial-truth qualification that gates formal forecasts, valuation, and market expectations. It
then accepts blank, caller-supplied revenue-growth, net-margin and P/E assumptions and mirrors the
canonical Python formulas. Until that gate passes, snapshot inputs are visible only as provenance;
no scenario arithmetic, reverse solve, or implied-price output is available. The 20-company
UI/formula seam is checked offline by `scripts/check_company_scenario_lab_ui.mjs`.

Market Expectations Gap v1 extends that same caller-only calculation: required revenue growth at
the current price minus the caller's revenue-growth assumption, holding the caller's margin and P/E
constant. Generated state keeps the selected gap null; it is not a forecast, probability, valuation
verdict or Henneth case.

Financial Results Coverage v1 maps the official PSX documents already indexed for each pilot name,
the three annual-history slots still required for revenue/PAT/EPS, and bounded candidate IDs for
future owner-approved qualification. It is metadata only: unknown periods remain unresolved,
half-year documents are not annual history, and audit-only facts are never promoted.

Forecast/Valuation Readiness v1 defines the exact activation boundary for future numeric models.
It requires three aligned annual consolidated PKR periods of current-parser revenue, attributable PAT
and basic EPS, strict post-period availability, compatible scale and exact official provenance. All 20
companies remain blocked today. Sector-driver registry coverage is shown separately and does not
activate an unimplemented forecast, valuation, market-expectations or numeric-impact model.

Causal Driver Evidence Map v1 resolves each existing driver-graph edge against retained
same-company official events and strict no-lookahead event studies. Its statuses are categorical and
each row states the next evidence required. It does not estimate causality, numeric impact, forecasts
or valuation; macro evidence remains excluded until stable source test identifiers exist.

Conditional Historical Benchmarks v1 adds exact same-company and same-sector context for every
retained operating event. It reuses strict no-lookahead analogue outcomes from the event-study state
instead of calculating returns in the browser or a second engine. Every current horizon aggregate is
suppressed because fewer than three mature exact analogues exist; peer, international, financial and
causal claims remain blocked.

The Investor Snapshot is backed by the persistent, reference-only Company Brain. It summarizes the
exact 21-domain coverage matrix, the five epistemic types, approved company context and a unified
typed timeline without copying producer facts into a second store. Unknown domains remain visible;
forecast and formal valuation remain blocked. `scripts/check_company_brains.py` and
`scripts/check_company_brain_ui.mjs` gate the 20-company state and UI seams.

The Thesis Monitor includes a separate private user notebook backed by owner-scoped Supabase
`company_theses` rows. It supports create/edit, reversible archive/restore and confirmed permanent
deletion, with one session-refresh retry. It never changes deterministic Henneth monitoring, and
fair-value assumptions are labelled private user input, never Henneth output. The notebook remains
inactive until the owner manually applies `docs/company_theses.sql` and verifies live RLS isolation;
an absent table renders “not activated.” `scripts/check_company_theses_security.mjs` and
`scripts/check_company_theses_ui.mjs` gate the offline contracts.

The deterministic Thesis Monitor also shows Management Delivery v2. Every active thesis keeps its
categorical backend status based only on same-company official events that arrive strictly after the
latest source observation and exactly match its assertion or conflict key. A separate guidance record
set compares only first-class same-company guidance objects with strictly later availability, exact
keys and self-source exclusion; it never changes a thesis record through loose matching. The browser
never matches or scores evidence, and companies without qualified guidance remain explicitly blocked.
Backend and UI contracts are checked by
`scripts/check_management_delivery.py` and `scripts/check_management_delivery_ui.mjs`.

Guidance & Contradictions v1 now supplies those first-class qualitative guidance/risk objects from
retained official document evidence only when an excerpt passes a strict assertion parser. Companies
with no qualifying evidence publish `no_guidance_objects`; contradictions require exact same-company
normalized-key conflicts among eligible objects. Numeric forecasts, valuation, advice language and
browser-side matching remain blocked. The backend and UI seams are checked by
`scripts/check_guidance_contradictions.py` and `scripts/check_guidance_contradictions_ui.mjs`.

Continuous Monitoring v1 composes only retained desk state into a source-health and change pulse for
each CI company. It marks the row `healthy`, `degraded`, `stale`, or `unknown` and links every alert
to its retained source; it never calls a first-seen page a change, treats a degraded source as fresh,
or produces a forecast, valuation, score, or trading instruction.

Financial Evidence Reconciliation v1 is the ledger behind earnings-bridge readiness. It keeps each
retained financial fact tied to its document, page and availability date, labels it eligible,
audit-only or quarantined, and preserves missing annual slots. It cannot promote legacy facts or
activate the still-blocked formal forecast, valuation or market-expectations outputs.

The Evidence Watchlist turns those deterministic monitoring records into a company-level checklist:
what official evidence would confirm the assertion, what would break it, what remains unobserved, and
which financial-readiness gate blocks quantification. It uses exact same-company source IDs only and
does not read private user theses or generate forecasts, odds, valuation, prices or advice.
`scripts/check_evidence_watchlist.py` and `scripts/check_evidence_watchlist_ui.mjs` gate the state and UI.

Ask Henneth receives only a capped Brain coverage/type/timeline projection plus the snapshot tool
readiness flags. Raw Brain payloads and unresolved references never enter model context; the server
continues to own the nine answer sections and reports every formal/snapshot output as blocked until
financial truth qualifies.

## Deployment and brand ownership

The Vercel project root is this folder, not the repository root. Git deployments therefore rebuild only when this directory changes.

Brand assets are byte-matched copies of the canonical files in `dashboard/`. Interface tokens, typography, hard-corner geometry, light/dark scheme behavior, and compact motion follow the production Henneth Desk design system; authentication and company data remain independent modules.
